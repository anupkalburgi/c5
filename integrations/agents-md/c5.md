## Project memory (c5)

This machine runs c5, a shared memory for coding work across sessions and agents, including each project's
decision log. Use the `c5` CLI (pass `--agent codex`, or your harness name, on writes):

- **First thing in every session**, run `c5 context` and continue from its "Last handoff" and "Current focus".
  Respect its "Decisions that apply", "Rules for every project" and "Ruled out" sections. If it says the
  folder is not linked to a c5 project, tell the user in your first reply and offer the suggested
  `c5 project init --name "…" --key …` (or `c5 project link KEY`); run it once they agree.
- **Before planning an approach or asking the user to choose**, run `c5 history "topic"` (decisions, rejected
  options, experiments and their outcomes, ideas, resources, oldest first). Follow decisions, don't repeat failed
  experiments unless what made them fail has changed, combine old ideas with what is known now, and cite ids.
- The brief's **Asked by the user** lists questions the user asked the agents about an item: answer each from
  evidence with `c5 answer ID "…"` (say so if you cannot tell), tell the user, then carry on.
- The brief's **Needs attention** lists what is overdue, due, ripe (what it waited on is done), waiting on the
  user, stale or going in circles: tell the user about the ones that concern them. `c5 pending --json` lists all.
- If the brief's About is not written yet, draft it from the README and record it once the user agrees
  (`c5 about set what "…"`, `c5 about add "…" --section stack|run|architecture|data`).
- Record experiments (`c5 add experiment "…" --hypothesis "…"`; outcome with `c5 done ID` or
  `c5 status ID failed|inconclusive -n "why" --retry-when "…"`) and resources you work with
  (`c5 add resource "…" --type dataset|table|model|endpoint|service|… --at LOCATION`). Never record credentials.
- **When the user decides or rules something out**, record it immediately:
  `c5 decide "…" --because "…" [-r "alternative: why not"] [--area A] [--for ID] [--global]`,
  `c5 reject "…" --because "…"`, or `c5 decide "…" -s OLD-ID` when changing an earlier decision.
- Starting a unit of work: `c5 focus ID --goal "why: what it serves"` (shows the decisions that apply), or
  `c5 add task "…" [--parent ID] --goal "…" --focus`.
- After meaningful steps or findings: `c5 log "…"` (one or two specific sentences; `-r path` for evidence).
- Bugs, regressions, loose ends, ideas, questions: `c5 add bug|regression|revisit|idea|question "…"`. For a
  question, keep the title short and put the options, their trade-offs and your recommendation in the body (`-b -`).
- Finished: `c5 done ID -n "what came out of it: result, commits, what it led to"`. Blocked: `c5 status ID blocked
  -n "…"`; `--after ID` brings it back as ripe once ID closes; `--due fri` only when the user gives a date;
  `c5 still ID -n "…"` when it is still needed but untouched.
- Before stopping: record any decisions not yet recorded, then `c5 handoff "where I stopped; what is next; open risks"`.
- Look before adding (`c5 ls --tree`, `c5 search "…"`), quote item ids in replies, and never let a failing `c5`
  command block the user's task.
